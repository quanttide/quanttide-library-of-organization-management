# 企业微信的职务

企业微信把职务建成成员的自由文本字段 `position`（职务信息），另设 `external_position`（对外职务）管对外展示。没有租户级的职务枚举，读取成员的返回体里也没有职级、序列一类的结构化字段。

## 定义

`position` 是通讯录成员的职务信息，写入长度 0~128 个 utf8 字符，由管理端或同步工具逐个填写。`external_position` 是对外职务，不超过 12 个汉字；设置之后对外展示以外部职务为准，否则展示 `position`。同一个成员因此有两个职务口径：内部记录与对外名号。

职务不进枚举意味着每次写入都是独立字符串，平台不保证同一名称在企业内写法一致，也不校验一人一职务。成员的分组靠部门与标签，可见性靠通讯录查看权限规则，两者都不以职务为依据。

`position` 之外，成员还有 `extattr`（扩展属性）与 `external_profile`（对外属性）两组自定义内容。

## 实现

### 读取

`GET https://qyapi.weixin.qq.com/cgi-bin/user/get` 按 `userid` 返回 `position` 与 `external_position`。字段受授权限制：应用只能读到可见范围内的成员，`position` 在代开发自建应用中需管理员授权才返回，第三方应用仅通讯录应用可获取。

### 写入

`POST https://qyapi.weixin.qq.com/cgi-bin/user/update` 在请求体中传 `position` 与 `external_position`。该接口「仅通讯录同步助手或第三方通讯录应用可调用」，普通自建应用不能改成员资料；批量场景另有异步导入接口（增量更新成员、全量覆盖成员），变化由通讯录回调通知的成员变更通知对外播报。

### 扩展属性

`extattr` 支持文本与网页两类属性，字段需先在 WEB 管理端添加，否则未知属性的赋值会被忽略。人事助手的花名册另有员工字段配置与花名册读写接口，字段范围超出通讯录内置字段。

## 与量潮职务的对照

| 企业微信字段 | 量潮职务（Title） |
| :-- | :-- |
| `position` 内部职务，自由文本，可为空 | 名分关系，任一时刻有且仅有一个 |
| `external_position` 对外名号，12 个汉字以内 | 职务是组织指代人的名号，对内对外同一个 |
| 无枚举、无唯一性校验，写入方各写各的 | 名号独立登记，从任职事实的记录处读取 |
| 调用权限在同步助手与第三方通讯录应用 | 职务变更与任职变更走同一登记流程 |

`external_position` 最接近量潮的名分语义，但它仍是资料字段：12 字上限、可为空、写入方分散在同步工具与第三方应用，撑不起「人是谁」的事实源。两个平台的差别，归根到底是资料字段与名分事实的差别。
